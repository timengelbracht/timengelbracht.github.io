# Tim Engelbracht — personal website

A quiet white page with robots peeking in from the edges. The paper list,
abstracts, links and teaser figures update themselves every week. Everything
else is a few small text files you can edit by hand.

## Quick start

```bash
./preview.sh            # first run sets up .venv; then syncs papers, builds and opens http://localhost:8000
```

or with `make` (run `make help` for the list):

```bash
make preview            # sync + build + serve
make build serve        # rebuild from what's already in data/ (no network)
make test               # offline tests
```

## What you edit by hand

| File | What it controls |
|---|---|
| `config.yml` | email, office, `url` + `tagline` (link previews), `cursor_robot` / `light_switch` (mouse-following robot and dark-mode switch, both off by default), name, bio (`[[keyword]]` gets a hand-drawn underline), "now" line, links, collaborators (`key` people up front, all other co-authors behind "+N more"), where papers come from |
| `content/themes.yml` | research themes ("what I work on") and the "work with me" open call, incl. optional student projects |
| `content/news.yml` | news list |
| `content/robot_today.yml` | "today the robot is …" lines. Every number must come from a paper; `source` says where |
| `content/failures.yml` | failure of the month (newest first). Add one with `.venv/bin/sitegen add-failure clip.mov --title "…" --caption "…"` (no date is shown, so it never goes stale) |
| `content/paper_links.yml` | per-paper extras: venue ("CVPR 2026", shown as a sticker), a missing project page, hiding a paper. Applied at build time, no sync needed |
| `assets/headshot.jpg` | your photo; a placeholder shows until it exists |
| `assets/cv.pdf` | your CV (the CV link appears once the file exists) |
| `assets/social.png` | the picture shown when the site is shared (1200×630) |
| `overrides/<slug>/teaser.mp4` or `.png` | optional: replace an automatically found teaser |

After editing, `make build serve` shows the result. Pushing to `main` redeploys.

## What happens automatically

`sitegen sync` (weekly on GitHub, or locally):

1. **Paper list** from Google Scholar (if `google_scholar_id` is set), Semantic Scholar
   (`semantic_scholar_ids`) and `extra_arxiv_ids`, merged by title.
2. **Details**: authors and abstract from arXiv, then Semantic Scholar, OpenAlex and DBLP.
   Abbreviated names ("Z. Bauer") are replaced by full ones when a source has them.
   The venue comes from the sources or from an arXiv comment like "Accepted to CVPR 2026";
   `content/paper_links.yml` wins if you set one there.
3. **Links**: project page, code, video and data found in the abstract, on the paper's first
   page on arXiv, in the code repository's homepage field, or at `project_page_guesses`.
   A project/data link is only used if the page loads and mentions the paper.
4. **Teaser**: project page video or image → arXiv Figure 1 → arXiv LaTeX source →
   Figure 1 region of the paper PDF → a doodle.

It never makes the site worse: if a source is down, papers keep last week's details,
links and teasers, and a paper only disappears when you add it to `exclude`.
At the end it lists co-authors not yet in `collaborators`, so you can decide.

`sitegen build` renders `site/` (not committed) from `config.yml`, `content/` and `data/`.

## Repository layout

```
config.yml                 site settings and paper sources
content/                   hand-written lists (news, robot lines, failures, link fixes)
data/publications.json     generated by sync, committed so builds are reproducible
assets/                    teasers/ (generated), failures/, headshot, cv
src/sitegen/
  cli.py                   python -m sitegen sync | build | serve | preview | add-failure
  sync.py                  the paper pipeline
  sources/                 scholar, semantic_scholar, arxiv, openalex, dblp
  links.py                 finding and verifying links
  teasers.py               picking a teaser
  media.py                 image/video conversion
  build.py                 rendering
  templates/index.html.j2  the page (HTML, CSS and JS in one file)
tests/                     offline tests (pytest)
.github/workflows/         deploy.yml (weekly sync + GitHub Pages), ci.yml (checks)
```

## Going live on GitHub Pages (once)

1. Create an empty repository on GitHub. Name it `timengelbracht.github.io` for
   `https://timengelbracht.github.io`; your existing project pages
   (`/SpotLight/`, `/Hoi-Dataset-Website/`, …) keep working.
2. `git remote add origin git@github.com:timengelbracht/timengelbracht.github.io.git && git push -u origin main`
3. On GitHub: Settings → Pages → Source: **GitHub Actions**.
4. Actions → "Sync papers and deploy" → **Run workflow**.
