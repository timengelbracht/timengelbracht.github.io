# personal-website

Tim Engelbracht's personal research website: a static page ("Peekaboo": plain
white, robot doodles peeking in) built by the `sitegen` package. The paper list,
abstracts, links and teasers update themselves; everything else is small YAML files.

Profile: **prototype**. These rules apply to every agent working in this repo.
Personal defaults live in `~/.claude/CLAUDE.md`; this file wins on conflicts.

## Stack
- Python 3.12, managed with `uv` (`uv sync`, `uv run ...`, `uv add ...`).
  Never use pip or conda directly.
- Jinja2 for the page, requests + BeautifulSoup for sources, Pillow / PyMuPDF /
  imageio-ffmpeg for teasers.
- Lint/format: ruff. Types: mypy. Tests: pytest.

## Layout
```
src/sitegen/              library + CLI (importable, tested)
src/sitegen/templates/    index.html.j2: the whole page (HTML, CSS, JS)
config.yml                site settings and paper sources
content/                  hand-written YAML (themes, robot lines, failures, paper fixes)
data/publications.json    generated by `sitegen sync`, committed
assets/                   headshot, teasers/ (generated), failures/, social.png
overrides/<slug>/         optional hand-picked teasers
tests/                    pytest, offline
tools/check_structure.py  size limits
docs/                     ARCHITECTURE.md, decisions/
site/                     generated by `sitegen build`, gitignored
```

## Commands
- Setup: `uv sync`
- Site: `uv run sitegen sync | build | serve | preview | add-failure`
  (`./preview.sh` = sync + build + open the browser)
- Tests: `uv run pytest`
- Lint: `uv run ruff check . && uv run ruff format --check .`
- Types: `uv run mypy src`
- Structure: `uv run python tools/check_structure.py`
- Duplication: `uv run pylint --disable=all --enable=duplicate-code src`
- Module boundaries: `uv run lint-imports`
- All checks: `uv run pre-commit run --all-files`

## Architecture & reuse — read before writing code
`docs/ARCHITECTURE.md` is the map of this codebase: which module owns what.
Read it at the start of every coding task.

**Before writing new code**
1. Search first: `grep -rn "def <likely_name>" src/` and check
   `docs/ARCHITECTURE.md`. If something similar exists, **extend or reuse it**.
2. For anything bigger than ~50 lines, a new module, or a change touching more
   than 3 files: use the `plan-change` skill before editing.

**Where code goes**
- One module per responsibility (see `docs/ARCHITECTURE.md`). A new paper
  source is a new file in `sources/`; a new teaser source is a method on
  `teasers.Teasers` added to its chain; a new page section is template + one
  content file + a few lines in `build.run`.
- Imports flow one way (enforced by `lint-imports`):
  `cli → sync | build | failures → teasers → links → sources → http | media | venues → util | paths`.
  Need to import "upwards"? The code is in the wrong module — move it.
- Site content (names, venues, links, wording) lives in `config.yml` /
  `content/`, never in Python.

**Size and duplication limits (enforced by tools/check_structure.py,
pylint duplicate-code and ruff complexity — the edit hook reports violations)**
- Files ≤ 400 code lines, functions ≤ 60 lines, cyclomatic complexity ≤ 15.
- No duplicated blocks (≥ 10 similar lines): extract a shared function.
- When a limit is hit, refactor. Never silence the check with `noqa` or by
  raising limits unless Tim agrees.

**Don't**
- Don't create `*_v2.py`, `utils2.py`, `*_final.py`: change the existing code.
- Don't add a dependency for something ~20 lines of code can do; ask first.
- Don't build frameworks for hypothetical future needs.
- Don't leave dead code, commented-out blocks or unused files behind.
- Never invent paper facts (numbers, venues, links): they come from the
  papers/sources or from Tim. Unverifiable links are dropped, not guessed.
- After a refactor, update `docs/ARCHITECTURE.md` in the same change.

## Code rules
- Optimise for iteration speed, but keep `src/` importable and tests green.
- Type hints on public functions in `src/`.
- Prefer simple functions over class hierarchies. No premature abstraction.
- At least a smoke test for each new module in `src/`; tests never hit the network.
- Never hardcode absolute paths or credentials (`CLAUDE.local.md` holds local details).
- Don't change config keys or CLI commands without saying so.
- Done means: `uv run pytest`, `uv run ruff check .`, `uv run mypy src`,
  `uv run python tools/check_structure.py` all pass, `uv run sitegen build`
  works, and `docs/ARCHITECTURE.md` reflects any new or moved module.

## Decisions
Non-obvious choices get a short record in `docs/decisions/NNNN-<slug>.md`:
context, options, decision, why.

## Git
- Small commits, imperative messages (`Add OpenAlex fallback`).
- Never commit `site/`, `.venv/` or secrets. `data/` and `assets/teasers/` are
  committed on purpose (reproducible builds).
- Don't push or rewrite history unless Tim asks.
